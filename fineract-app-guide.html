Sim — e já existe um app pronto como base!

O ecossistema Mifos/Fineract fornece apps mobile prontos e open-source para Android e iOS, que você pode usar como white-label e personalizar.

✅

App mobile pronto

O Mifos Pay (Kotlin Multiplatform) está nas lojas Google Play e App Store. Open-source, white-label, conecta direto ao Fineract.

🔌

API REST pública

O Fineract expõe 400+ endpoints REST. Qualquer app (Flutter, React Native, Angular, etc.) consome a mesma API. Players se integram via adapters.

🔧

Plugin Architecture

Cada integração com player (Mercado Pago, PIX, Stripe) vira um Plugin JAR carregado pelo Fineract sem modificar o core.

🎯

Modelo Mental CorretoO Fineract é o banco (guarda dinheiro, faz contabilidade, gerencia contas). Os players (PIX, Mercado Pago, Stripe) são os canais de entrada/saída de dinheiro. O app mobile é a interface do usuário. Você precisa conectar os três.

💡

Payment Gateway vs Core BankingMercado Pago, PagBank e Stripe são gateways de captura de pagamento — eles movem dinheiro mas não gerenciam contas bancárias completas. O Fineract é o ledger (livro-caixa) onde cada transação é registrada com contabilidade dupla entrada.

PIX
Bacen — Pagamento Instantâneo
🔧 Alta Complexidade
Sistema de pagamento instantâneo do Banco Central. Obrigatório para qualquer banco digital brasileiro. Transferências em segundos, 24/7, taxa zero para PF.
PIX Transferência PIX Cobrança QR Dinâmico Chaves DICT
Como integrar:
→ Registrar como PSP no Bacen (ISPB)
→ Ou usar um PSP habilitado como intermediário (Celcoin, BancaA3, SWAP)

→ Mapear chave PIX → InteropIdentifier no Fineract

Guia Técnico

Como integrar um player na prática

O padrão de integração é sempre o mesmo: 4 passos independente do player escolhido.

🔄

Padrão Universal de Integração

Funciona para qualquer player

1

Registrar Payment Type no Fineract

Criar um paymentType (ex: "PIX", "Mercado Pago") para rastrear a origem de cada transação na contabilidade.

2

Criar o Adapter (microserviço/plugin)

Um serviço que "fala" o protocolo do player externo (API deles) e traduz para chamadas REST do Fineract.

3

Configurar Webhooks bidirecionais

Player → chama seu adapter quando pagamento é confirmado. Fineract → emite evento via Kafka quando transação é processada.

4

Reconciliação automática

Job noturno (Spring Batch / COB) compara extrato do player com transações no Fineract. Diferenças geram alertas.

💙

Exemplo: Integrar Mercado Pago

// 1. Criar PaymentType no Fineract POST /api/v1/paymenttypes { "name": "Mercado Pago", "isSystemDefined": false } // 2. Criar cobrança MP (seu adapter chama MP API) POST https://api.mercadopago.com/v1/payments { "transaction_amount": 100.00, "payment_method_id": "pix", "external_reference": "fineract-account-456" } // 3. MP envia webhook quando aprovado POST https://seu-adapter.app/webhook/mp { "status": "approved", "external_reference": "fineract-account-456" } // 4. Adapter credita no Fineract POST /api/v1/savingsaccounts/456/transactions?command=deposit { "amount": 100.00, "paymentTypeId": 5, // ID do Mercado Pago "accountNumber": "MP-TXN-12345" }
✅

Contabilidade automáticaAo chamar o deposit com paymentTypeId, o Fineract registra automaticamente o journal entry: Débito na conta de recebíveis do gateway, Crédito na conta do cliente.

🇧🇷

Integração PIX — O caminho mais rápido para o Brasil

🏁 Opção 1: Via BaaS (Recomendado)

Use Celcoin, SWAP, Dock ou BancaA3 como intermediário. Eles têm licença Bacen, você só integra a API deles.

  • PIX em dias, não meses
  • Sem licença Bacen própria
  • API simples + webhooks
  • Custo por transação

🔧 Opção 2: Via Mercado Pago / PagBank

MP e PagBank já têm PIX integrado nas suas APIs. Você cria uma cobrança PIX no MP e eles cuidam do clearing.

  • Integração conhecida
  • QR Code PIX nativo
  • Muito bem documentado
  • Liquidação D+1

🏛️ Opção 3: PSP Direto (Bacen)

Registrar sua empresa como PSP no Bacen e acessar o SPI (Sistema de Pagamentos Instantâneos) diretamente.

  • Controle total
  • Menores custos por volume
  • Processo longo (6-18 meses)
  • Requer regulação

Roteiro: do zero ao app bancário completo

4 fases práticas para lançar seu app bancário com Fineract e integrações com players.

Fase 1 · Meses 1-2

🏗️ Fundação

  • Deploy Fineract (Docker/K8s)
  • Configurar PostgreSQL + TLS
  • OAuth2 + JWT + RBAC
  • Produto: Conta Corrente
  • Onboarding via API (CPF)
  • Fork do Mifos Pay
  • Design system / branding
Fase 2 · Meses 2-4

💳 Pagamentos Básicos

  • Integrar BaaS (Celcoin)
  • PIX via BaaS adapter
  • Mercado Pago adapter
  • Recarga via boleto/cartão
  • Webhook → Fineract deposit
  • Notificações push (FCM)
  • Extrato em tempo real
Fase 3 · Meses 4-6

🚀 Features Avançadas

  • Cartão virtual (parceria)
  • PagBank split payment
  • Crédito pessoal (Loan API)
  • Investimentos (savings)
  • Cashback engine
  • KYC Nível 2 (renda)
  • Open Finance fase 1
Fase 4 · Meses 6-12

🏦 Marketplace

  • Multi-tenant sellers
  • Motor de comissões
  • FIDC / Investidores
  • Cielo/Rede para POS
  • Open Finance fase 2
  • Stripe para global
  • Regulação Bacen
💡

Stack de tecnologia recomendada
• Backend: Apache Fineract (Java 21) + microserviço de adapters (Node.js ou Go)
• App Mobile: Mifos Pay fork (Kotlin KMP) ou Flutter com pacote fineract_sdk
• API Gateway: Kong / AWS API Gateway / Nginx
• Eventos: Apache Kafka ou RabbitMQ
• Cloud: AWS (EKS) ou GCP (GKE) com PostgreSQL RDS/Cloud SQL
• PIX (fase 1): Celcoin ou SWAP (BaaS) para ir rápido

Atenção: regulação
Para emitir conta bancária com IBAN/ISPB próprio você precisa de licença Bacen (IP — Instituição de Pagamento). Para começar, use um BaaS como banco parceiro e depois solicite sua própria licença quando tiver volume/capital.
